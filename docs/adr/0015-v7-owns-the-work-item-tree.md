# ADR-0015 — v7 owns the work-item tree; we write sidecars

**Status:** Proposed
**Date:** 2026-11-16
**Spec:** §2, §3.1–§3.3

## Context

v7 keeps work items as initiatives, epics and tickets in `tickets.toml` and plan files, written
by `tickets.py`. `tickets.py` takes no lock, and its `move` verb writes `next_id` into the
shared `tickets.toml`. Leaf frontmatter is regenerated by `pull`.

## Decision

**v7 decides what the work is; we decide what it costs, what order it runs in, and whether it
may start.** If v7's tree can express a fact, we do not store it. We never write
`tickets.toml`, leaf frontmatter, or a plan file except through `tickets.py mark`. Our data
lives in sidecars:

| Data | Home |
|---|---|
| estimates, class, lane (plan time, single writer) | `l3io.toml` beside `tickets.toml` |
| actuals, fix iterations, completion evidence (concurrent) | a per-ticket sidecar beside the plan file |
| calibration, events, ADR register, notices (project-wide) | `{output_folder}/l3io/` |

`issues.yaml` dissolves into v7's `backlog/`; its audit survives as a doctor mode.

## Consequences

Writes to our own files keep `flock` and never contend with `tickets.py`. A hand-set
`estimate` or `l3io_*` key in `tickets.toml` is still read, as an override.
